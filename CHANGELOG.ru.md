# История изменений

[English](CHANGELOG.md) · [Русский](CHANGELOG.ru.md) · [简体中文](CHANGELOG.zh-CN.md)

## 1.5.1

- Исправлена кнопка Terminal на HOME: событие мыши больше не передаётся вместо координат и не вызывает ошибку «Session position is invalid».
- Добавлено перетаскивание локальных файлов в терминал. Пути экранируются для стандартной оболочки ОС и вставляются без отправки команды; пробелы и кириллица сохраняются.
- Исправлены дублирование истории при получении живого вывода, координаты полосы прокрутки при масштабировании канваса и сохранение позиции прокрутки при изменении размера терминала.
- Добавлено настраиваемое круговое меню из PR #29. По умолчанию оно выключено; включается в «Настройки → Агенты → Быстрый запуск». Отключение сохраняет выбранные действия.
- У заметок появилась кнопка-крестик для удаления (PR #30).
- Добавлена вставка пути проекта в окне запуска агента и исправлена обработка служебных строк буфера GNOME (PR #27 и #31). Для ссылок из терминала можно выбрать встроенный или системный браузер (PR #28).
- Восстановлено получение лимитов Claude Code с исправленным выбором хранилища учётных данных (PR #25).

## 1.5.0

- Конкурирующие обработчики ПКМ заменены единым контекстным диспетчером. Пустой канвас, цветные зоны и заметки показывают собственные действия; настраиваемый безопасный launcher агентов/терминала используется и в поисковой палитре команд `Cmd/Ctrl+K`.
- Заметки стали полноценными сохраняемыми окнами канваса: редактирование, drag, resize по восьми направлениям, snapping, удаление, детерминированная привязка к зоне и маркеры на мини-карте. Реализация адаптирует исходные идеи заметок и быстрого launcher из PR #23 и сохраняет авторство @TroopJostle.
- Доделано перемещение цветных зон: полностью находящиеся внутри терминалы, Browser/plugin-окна и заметки двигаются синхронно с зоной и сохраняются один раз при отпускании. Targeting зон, магнитная сетка и правила bounds больше не захватывают частично пересекающиеся окна и не телепортируют их после жеста.
- Добавлен обычный click-to-front для всех окон канваса. Нативная поверхность Browser теперь подчиняется renderer-стеку, а диалоги запуска ограничиваются границами до первого кадра и не вспыхивают за правой границей приложения.
- Settings и все меню канваса переведены на новый дизайн с общими токенами приложения, официальными Lucide/provider assets и единым масштабом UI-хрома `0.85–1.25`. Смена палитры автоматически перекрашивает меню, не затрагивая zoom канваса и размер шрифта терминала.
- В «Основные» добавлены независимые настройки сохранения цветных зон и заметок после выхода. Выключение оставляет объекты в текущем запуске, но исключает только выбранную коллекцию из snapshot следующего запуска.
- Управление мини-картой разделено на явные режимы «Клик» и «Перетаскивание». Drag повторяет направление grab пустого канваса без начального прыжка камеры, а неподвижное нажатие в Drag-режиме не выполняет click navigation.

## 1.3.0

- Добавлено опциональное восстановление окон терминалов. CanvasTTY сохраняет только identity окна, provider/profile, заголовок, папку проекта, позицию и размер; агенты продолжают сессию через нативный project-scoped continue mode, а PTY scrollback и capabilities не сохраняются.
- Добавлены именованные пастельные области канваса из контекстного меню пустого пространства и RTS-мини-карта вокруг текущей камеры. HOME и маркеры окон двигаются по единой проекции без auto-fit и искажений; пограничный маркер HOME появляется только после его полного выхода за карту.
- Бинды навигации канваса теперь принимают Mouse3/Mouse4/Mouse5, drag средней кнопкой остаётся прямым fallback для pan. Исправлено владение wheel: список сессий и focused input-поверхности прокручиваются локально, пока пользователь явно не включил перехват канвасом.
- Исправлена обрезанная первая отрисовка Grok Build: запуск, restart и restore ждут реальный размер сетки xterm от renderer. Resize терминала и смена палитры сохраняют текущую позицию scrollback.
- В «Оформлении» появился настраиваемый фон всей строки агента: серый для простоя/недоступного/завершённого состояния, зелёный для работы и жёлтый для ожидания ответа; доступен однотонный режим.
- Лимиты Claude теперь запрашиваются с OAuth credentials текущего пользователя приложения. Отсутствие локального токена означает необходимость входа, а не ошибочное «Требуется подписка».
- CanvasTTY больше не восстанавливает, не показывает и не фокусирует окно из-за отклонённого второго запуска или фоновой активности плагина/браузера, поэтому приложение самовольно не переключает виртуальные рабочие столы.
- Добавлены краткий выключатель status hooks в «Агентах», раскрываемый FAQ в «О приложении» и явное доверие к каждому опциональному plugin agent hook. После install/update хуки выключены и запускаются в изолированном процессе без внутренних capabilities CanvasTTY.

## 1.2.8

- Qwen Code добавлен как полноценный launcher в HOME, Settings, поиск CLI, профили Normal/YOLO, plugin SDK и ограниченный MCP-мост встроенного браузера. Используются официальный mark Qwen и только launch-scoped конфигурация.
- В HOME и его настройках появилась строка лимитов Qwen. Поскольку Qwen Code умеет работать с разными облачными и локальными model providers и не имеет универсального quota-read protocol, CanvasTTY показывает явную причину недоступности, а не выдумывает usage data.
- Общий статус открытой агентской сессии заменён на защищённый локальный lifecycle gateway. Codex, Claude Code, Qwen Code, Kimi Code, OpenCode, Hermes и Grok Build сообщают состояния «Простаивает», «Работает» и «Ждёт ответа» через provider hooks без передачи текста prompt/response; terminal-title markers Claude/Qwen сохранены как fallback совместимости.
- Исправлена гонка, при которой поздний bootstrap snapshot возвращал уже подтверждённый lifecycle агента в состояние «Статус недоступен». Метаданные сессии теперь имеют монотонную ревизию от main-процесса, а renderer отклоняет устаревшие статусы, сохраняя начальный вывод терминала.
- При изменении размера карточки или окна приложения сохраняется активная позиция terminal scrollback вместо прыжка в начало сессии.
- Keyboard focus сегментированной настройки остаётся внутри выбранной кнопки; между переключателем захвата wheel/pinch и условным редактором клавиши восстановлен правильный отступ.

## 1.2.7

- Добавлен узкий мост для управления Hermes Desktop HUD из плагинов. Хост открывает только проверку статуса, запуск в HUD-режиме и закрытие через `hermes:hud`; плагин не может выбирать исполняемый файл, аргументы или PID.

## 1.2.6

- Исполняемые файлы provider CLI теперь один раз определяются при старте и затем используются терминалами, лимитами и agent-browser через один абсолютный launcher; для отсутствующих и неисполняемых команд возвращается структурированная диагностика.
- Неудачные сессии HOME теперь показывают полную очищенную диагностику по наведению или фокусу с клавиатуры, позволяют скопировать её и объясняют тихое завершение кодом выхода. Всплывающая панель верхнего слоя сохраняет трёхрядный scroll viewport и красный danger rail ошибочной сессии.
- Упакованное macOS-приложение теперь находит CLI из Homebrew и официальный пользовательский OpenCode в `~/.opencode/bin` даже при запуске через Finder с минимальным `PATH`.
- CI теперь собирает macOS-приложение и проверяет реальный поиск CLI с минимальным `PATH` для каждого pull request и обновления `main`, а не только во время релиза.

## 1.2.5

- OpenCode, Hermes и Grok Build добавлены как полноценные launcher-провайдеры в Linux, macOS и Windows: официальные marks, штатное YOLO-поведение только на время запуска, поиск CLI в Windows, покрытие plugin SDK и ограниченная интеграция со встроенным браузером через MCP там, где она поддерживается.
- В Settings появился независимый раздел **Агенты**: видимость launcher-кнопок и строк лимитов HOME сохраняется раздельно, скрытие launcher не затрагивает существующие сессии, а HOME dock автоматически перераспределяет ширину видимых кнопок.
- К реальным лимитам Codex, Claude и Kimi добавлены source-backed adapters OpenCode Go и Grok Build. Пятирядный HOME-виджет лимитов теперь переключается в компактную плотность по реальной высоте, поэтому countdown и usage rail полностью остаются внутри дефолтной плитки.
- Appearance получил независимые preset/custom-цвета HOME и цвета фона Canvas, а также узоры «Диагонали» и «Кольца». Цвет Canvas больше не перекрашивает HOME-виджеты, а верхняя полоса Settings визуально отделена от прокручиваемого содержимого.
- Исправлен clip нативного Browser viewport: встроенные страницы остаются внутри рабочей области и не перекрывают chrome приложения. Добавлена видимая идентификация DEV/release-сборки и нормализовано отображение provider marks.

## 1.2.4

- Бандлы macOS теперь явно подписываются ad-hoc с отключёнными hardened runtime и notarization для бесплатного способа распространения; перед загрузкой артефактов релизный workflow запускает строгую проверку `codesign`.
- Инструкции по установке уточняют, что ad-hoc подпись подтверждает целостность бандла, но не предоставляет Developer ID и notarization. Пользователям macOS следует заменить артефакты `1.2.2` и `1.2.3`, созданные до исправления, на `1.2.4` или новее.

## 1.2.3

- Добавлена GitHub-витрина плагинов с полной пагинацией, metadata-first манифестами, подсказками по платформе и версии хоста, поиском обновлений и входом через OAuth Device Flow.
- Установка и обновление плагинов усилены проверкой платформы, атомарным rollback, строгой валидацией манифеста, ограниченными batch-запросами метаданных, доверенными редиректами архивов и защищённым хранением OAuth и IPC.
- В SDK плагинов добавлен permission-gated метод `browser.open` для нормализованных HTTP(S)-адресов: единый awaitable broker создаёт или переиспользует одну встроенную Browser-карточку и сохраняет её до подтверждения успеха.

## 1.2.2

- Переработана навигация по канвасу: прокрутка двумя осями теперь по умолчанию панорамирует канвас, а щипок и `Cmd/Ctrl+колесо` масштабируют от точки фокуса; прежний режим «прокрутка — масштаб» остался в настройках с сохранением направления и чувствительности.
- Логическое владение вводом для виджетов: виджет захватывает колесо после явного клика или настраиваемой задержки наведения, удерживает фокус до клика вне виджетов, режимы захвата `Off / On / Key`; отдельный удерживаемый биндинг временно захватывает всю навигацию канваса, включая перетаскивание.
- Сохранена непрерывность жестов через поверхности нативного Браузера: владение «страница/канвас» фиксируется на 250 мс неактивности колеса, щипок и `Cmd/Ctrl+колесо` всегда масштабируют канвас, а сфокусированная страница Браузера продолжает прокручиваться нативно при выключенном захвате.

## 1.2.1

- Canvas-приложения плагинов теперь открываются и повторно фокусируются в нативном масштабе `1.0`, без размытия от дробного scale; прозрачный фон iframe также убирает светлую полосу вокруг скруглённого окна плагина.
- Semantic summaries терминала и браузера теперь заранее резервируют ширину под counter-scale и сохраняют содержимое по центру, поэтому иконки и текст не обрезаются при сильном отдалении canvas.

## 1.2.0

- Нативный window chrome на macOS: скрытый title bar с traffic-light кнопками, компактный brand bar и корректное поведение в native fullscreen; на Linux и Windows остаётся прежняя кастомная рамка.
- Секреты плагинов с OS-шифрованием через Electron safeStorage (fail-closed, если системный keyring недоступен): проверка permission на каждый вызов, квоты, события изменений и очистка при удалении плагина.
- Плагины могут добавлять собственный пункт настроек (открывается в sandboxed frame), задавать минимальные размеры canvas и открывать второй canvas того же плагина рядом с текущим.
- HOME-виджеты плагинов показываются рядом с встроенными в Appearance → HOME composition и добавляются/убираются как родные — это закрывает известную недоработку 1.1.0; в Settings → Plugins остались только установка и удаление.
- Опциональные модули плагинов: выбор при установке, проверка SHA-256 и точного размера каждого файла, атомарная переконфигурация с rollback, а module-derived permissions единообразно применяются к SDK-авторизации и CSP ресурсов плагина.
- События изменения storage плагина теперь рассылаются из main-процесса: canvases, HOME-виджеты и отдельные окна одного плагина видят записи друг друга.
- Загрузки плагинов усилены: редиректы ограничены хостами `api.github.com` и `raw.githubusercontent.com`, загрузка модулей использует retry/backoff из 1.1.0.
- Задокументирована trust model опциональных модулей: целостность файлов привязана к манифесту плагина, получаемому с GitHub по TLS без отдельной подписи.

Известная недоработка: установленные плагины пока нельзя обновить на месте — для получения новой версии удалите плагин и установите заново. Действие обновления запланировано.

## 1.1.0

- Native-страницы браузера масштабируются под zoom канваса через Chromium zoom factor (ограничен 0.5–3): содержимое браузера следует масштабу канваса при любом zoom.
- Viewport bounds браузера сообщаются синхронно, а native view остаётся видимым во время панорамирования, перетаскивания и resize канваса; это исправляет проблему 1.0.2, когда native browser view мог перекрыть не-maximized окно и заблокировать управление канвасом.
- Web contents вкладки браузера получают фокус по pointer-down на канвасе — ввод попадает на страницу без лишнего клика.
- В Settings добавлен переключатель индикаторов присутствия агентов в браузере (по умолчанию включён): badges/cursors больше не появляются при аутентификации, курсоры рисуются точками без имён и показываются только для агентов, реально работавших с браузером.
- Загрузка плагинов с GitHub повторяется до трёх раз с backoff при временных сбоях (таймауты, ошибки соединения, HTTP 408/429/5xx, оборванные потоки).
- Добавлен перезапуск терминальной сессии: кнопка restart на завершённых карточках и shortcut `Ctrl+D`; PageUp/PageDown листают scrollback в обычном буфере, а курсор терминала стал блоком.
- Wheel zoom поверх приложений теперь включён по умолчанию.
- Документация синхронизирована на английском, русском и упрощённом китайском.

Известная недоработка: кастомизация HOME-раскладки для внешних плагинов не завершена — плитки плагинов пока нельзя размещать и перемещать в редакторе раскладки HOME. Задача открыта, вклад сообщества приветствуется.

## 1.0.2

- Встроенный браузер открыт из HOME как перемещаемое и изменяемое по размеру canvas-приложение с доверенными tabs/navigation, downloads, site dialogs, безопасным восстановлением вкладок, очисткой browser data, semantic summaries и стабильной native-view geometry во время движения камеры/карточки.
- Для сессий Claude Code, Codex и Kimi, запущенных через CanvasTTY, добавлена scoped browser automation через встроенный stdio MCP helper и аутентифицированный Unix socket текущего пользователя или защищённый Windows named pipe; TCP listener, remote-debugging port, произвольный JavaScript, cookie/storage API и raw CDP не открываются.
- Добавлены badges/cursors подключённых агентов, изоляция activity по агентам, element refs с document revision, FIFO mutations по вкладкам, request deduplication, ограниченные concurrency/rate limits/timeouts, работа с dialogs/downloads и очищенные screenshots с fail-closed при невозможности надёжно закрыть чувствительные области.
- Добавлен постоянный очищенный hash-chain аудит браузера в Electron `userData/browser/audit`: ротация при 100 МБ, retention ротированных файлов 30 дней, integrity checks и fail-closed agent mutations, если обязательный pre-action audit нельзя записать.
- Карточка браузера интегрирована с terminal-equivalent выбором на канвасе, click/hover focus, снятием выбора по пустому канвасу, window actions, wheel zoom поверх приложений и стабильной renderer surface во время перемещения native view.
- Windows agent transport усилен встроенным native named-pipe host, доступным только точному SID текущего пользователя; release pipeline дополнен реальными Electron/provider smoke tests.
- Исправлен secret audit репозитория для linked Git worktree: имена repository metadata игнорируются до определения типа entry, при этом personal path в публикуемых файлах по-прежнему обнаруживается.
- Документация браузера, безопасности, локальных данных, audit log и релиза синхронизирована на английском, русском и упрощённом китайском.

Известная проблема: если главное окно CanvasTTY изначально открылось не maximized, запуск Browser может растянуть native browser view на всё окно и сделать управление канвасом недоступным. В этом prerelease запускайте CanvasTTY maximized до открытия Browser; исправление запланировано на следующий patch.

## 1.0.1

- Добавлен перенос строки в терминале через `Shift+Enter` без отправки текущего промпта.
- Исправлены выбор терминала и клавиатурный фокус: ввод сразу идёт в xterm выбранной живой карточки, а нажатие по пустому канвасу снимает выбор и рамку.
- Добавлен опциональный автофокус при наведении с задержками входа и выхода: медленно (`500ms`), обычно (`250ms`) и быстро (`80ms`). Программный hover focus больше не отправляет focus-report sequences в TUI агента и не перебрасывает его в начало истории.
- Добавлены независимые настройки направления колеса для терминала и канваса. По умолчанию колесо вниз прокручивает терминал вниз, а зум канваса сохраняет прежнее направление.
- Вывод PTY объединяется в renderer-обновления по 16 мс, а повторное копирование строки scrollback заменено ограниченным chunk-буфером. Это устраняет мигание при больших объёмах вывода и сокращает сбросы истории.
- Очереди записи настроек, реестра плагинов и разрешений медиакаталогов теперь восстанавливаются после временных ошибок файловой системы, а метаданные клиентов провайдеров соответствуют версии приложения в пакете.
- Добавлено полное руководство по runtime-плагинам на упрощённом китайском, синхронизированы инструкции по терминалу на трёх языках и описаны локальные данные плагинов, медиапапок и браузера.
- Добавлена лицензия MIT и локализованы Security, Changelog, Architecture и UI Contract.

## 1.0.0

- Добавлена лёгкая локальная стартовая страница, которая появляется до инициализации настроек, плагинов, медиа и IPC; ошибки bootstrap теперь показываются на видимой странице с fallback на нативный диалог вместо пустого окна.
- Добавлена блокировка второго экземпляра Electron: повторный запуск восстанавливает и фокусирует существующее окно.
- Координаты указателя терминала преобразуются из CSS-трансформации канваса обратно в координаты layout xterm, поэтому выделение текста, mouse reporting в vim/tmux и прокрутка работают при любом масштабе.
- Переработаны сочетания буфера обмена терминала: копирование через `Ctrl+C` при выделении, `Ctrl+Shift+C` или `Cmd+C`; вставка через `Ctrl+Shift+V`, `Cmd+V` или `Shift+Insert` с использованием `Terminal.paste`. Сочетания привязаны к физическим клавишам и работают с нелатинскими раскладками.
- Добавлен smoke harness упакованного приложения (`CANVASTTY_SMOKE_TEST=1` печатает `CANVASTTY_SMOKE_READY` после первого кадра) и подключён к Linux release pipeline под `xvfb-run` с FUSE2.
