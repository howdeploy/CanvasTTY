## Unreleased

- Эндпоинт оркестрации агентов стал явной настройкой (Настройки → Агенты → «Эндпоинт оркестрации агентов», `agentControlEnabled`, по умолчанию выключен; `--agent-control` / `CANVASTTY_AGENT_CONTROL=1` по-прежнему принудительно включают его на один запуск), которая запускает и останавливает эндпоинт на лету, а в диалог запуска рядом с профилем normal/YOLO добавлена роль **Оркестратор**: сессия сохраняет провайдера, для которого открыт диалог, получает в окружении `CANVASTTY_CONTROL_CONNECTION` и `CANVASTTY_CONTROL_CLI`, чтобы встроенный CLI работал без настройки, показывает бейдж «Оркестратор», сохраняет роль при восстановлении, а при выключенном эндпоинте диалог предлагает сначала включить его, ничего не включая молча. `create` эндпоинта теперь принимает любого провайдера-агента (`codex, claude, qwen, kimi, opencode, hermes, grok, omp, pi`) и в ответах `create` и `list` сообщает `capabilities { result, menus }` для каждого воркера: оба значения `true` только для Codex; у остальных провайдеров `screen` не содержит взаимодействия с меню, `choose`/`dismiss` завершаются ошибкой `NOT_SUPPORTED`, `send` опирается только на статус idle, а `result` завершается как `no_result`.
- Добавлен нативный CLI оркестрации Codex (`agent-control/canvastty-control.mjs`, описан в `agent/orchestrator/SKILL.md`), включаемый флагом `--agent-control` или `CANVASTTY_AGENT_CONTROL=1`: локальный контроллер создаёт сессии Codex в каталоге проекта, отправляет задачи, наблюдает ограниченный вывод терминала относительно ревизии экрана и получает итоговый ответ. Контроллер видит только созданные им сессии, гранты привязаны к поколению сессии, идентификаторы мутаций дедуплицируются, и только управляемые сессии включают аутентифицированный захват результата через Stop-hook. Автоматического одобрения и удаления терминалов нет.
- Добавлен опциональный компаньон Even G2 (Настройки → Управление → Even G2, приложение-компаньон в `integrations/even-g2`): обнаружение через Bonjour, короткоживущее сопряжение SRP-6a с шестизначным кодом и явным подтверждением устройства, шифрованные локальные запросы и аудио, гранты на сессию, ограниченное отображение терминала на HUD очков, локальное распознавание речи через закреплённый helper transcribe.cpp (поставляется только для macOS) и создание сессий через обычный лаунчер. Итоговый ответ хода Codex попадает в компаньон только для сессий, запущенных при включённом компаньоне: runtime-hook передаёт его по отдельному гранту сессии с ограничением 4000 символов, а gateway отклоняет его для любой другой сессии.

- На стандартной сессии запрещены разрешения браузера и устройств: запросы разрешений, их проверка и обработчики устройств теперь отказывают, поэтому plugin-окна и shell не могут получить доступ к камере, микрофону, геолокации и уведомлениям. Встроенный браузер сохраняет собственную политику отдельного partition.
- Упакованные сборки усилены Electron fuses: отключены переменная окружения `NODE_OPTIONS` и аргументы CLI inspect, включена проверка целостности embedded asar. `runAsNode` намеренно оставлен включённым, потому что provider CLI и agent runtime запускают встроенные helper-процессы через `ELECTRON_RUN_AS_NODE`; шифрование cookie не включено, поскольку переход односторонний.
- Добавлено восстановление после потери renderer-процесса: main-процесс пишет в лог причину и код выхода и перезагружает поверхность приложения вместо пустого окна, а терминальные сервисы и живые сессии продолжают работать во время восстановления. Потеря utility/GPU-процесса логируется.
- Добавлен поиск по scrollback: `Ctrl+Shift+F` в сфокусированной карточке терминала открывает строку поиска с полем, счётчиком совпадений, переходом к предыдущему/следующему и закрытием. `Enter` переходит к следующему совпадению, `Shift+Enter` — к предыдущему, `Escape` закрывает строку и возвращает фокус терминалу, поэтому нажатия не утекают в PTY. В режиме semantic summary строка скрыта.
- Пока заголовок карточки не переопределён пользователем, в шапке показывается заголовок, заданный провайдером через OSC 0/2; если провайдер его не задаёт, используется прежнее отображение пути. Переименование имеет приоритет навсегда, а заголовок провайдера только отображается: он никогда не записывается обратно и не сохраняется.
- Добавлен элемент канваса «Показать всё»: он вписывает зону HOME и все окна с отступом в пределах существующего диапазона zoom `0.2–1.35`, а пустой канвас переходит в HOME. Команда также доступна в палитре канваса; клавиатурного сочетания для неё нет.
- Добавлена направленная фокусировка: `Alt+стрелки` (`Option` в macOS) переводит фокус на ближайшее окно в этом направлении среди карточек терминалов, встроенного браузера и plugin-canvas; цель обязана быть строго впереди, а перпендикулярное расстояние разрешает ничьи. Жест не срабатывает при переименовании и захвате сочетания и не затрагивает `Ctrl+K` и `Ctrl+,`.
- Добавлено выделение рамкой: `Shift+drag` по пустому канвасу выделяет все карточки терминалов, которые она пересекает (plugin-канвасы, встроенный браузер и стикеры не проверяются), а перетаскивание любого выделенного терминала двигает всё выделение на ту же дельту; нажатие без движения остаётся обычным кликом. Перетаскивание пустого канваса по-прежнему только панорамирует.
- В поиск палитры канваса добавлен путь сессии (cwd) рядом с названием и провайдером, поэтому сессию можно найти по рабочей папке. Второй палитры и нового сочетания клавиш нет.
- Добавлена очередь внимания в HOME: сессии, которым нужно подтверждение, и завершившиеся с ошибкой, выводятся только из session snapshots; строка заголовка и явное пустое состояние отображаются всегда, а клик по строке фокусирует эту сессию. Детали ошибки (триггер, popover, копирование) вынесены в одну общую реализацию, которую используют и очередь, и прежние строки сессий.
- Добавлено кольцо внимания на карточках, чья сессия ждёт подтверждения или завершилась с ошибкой, и настройка «Уведомлять о внимании» в «Настройках → Основные» (включена по умолчанию): она поднимает одно системное уведомление при настоящем переходе в состояние ожидания подтверждения или ошибки: повторные snapshots и уже виденные ошибки при восстановлении остаются молчащими, а ошибка, вызванная пользователем при перезапуске, тоже уведомляет. Переключение настройки сохраняется.
- Карточки теперь сообщают, отображают ли они живой вывод: в режиме semantic summary (zoom ниже 0.5) они перестают получать потоковый вывод, а scrollback остаётся каноническим и полным в пределах ограниченной истории; при возврате карточки в видимость пропущенный вывод воспроизводится один раз, а если скрытно было выведено больше, чем вмещает ограниченная история, самая старая часть этого отрезка потеряна, и повтор сообщает об этом вместо того, чтобы выдавать вывод за непрерывный.
- WebGL ограничен сфокусированной карточкой терминала: один контекст одновременно, освобождается при уходе фокуса, при потере контекста используется DOM-renderer. Отрисовка палитры и прозрачности не изменилась.
- В «Настройках → Обновления» появилась строка самообновления с честными состояниями: простой, проверка, доступно обновление (с версией), загрузка (с процентом, когда он известен), готово к установке и недоступно (dev, offline или ошибка). Загрузка и установка — явные действия пользователя, установка с перезапуском предлагается только после загрузки обновления, а в режиме разработки строка сообщает о недоступности и не выбрасывает исключение.
- Аудит секретов в репозитории больше не срабатывает на префиксы ключей внутри идентификаторов, поэтому имена вида `disk-…` и `task-…` не дают ложных срабатываний, а настоящие ключи по-прежнему находятся.
- Добавлены агенты Cursor, MiniMax Code, Devin и Antigravity (PR #63).
- Добавлены API-ключи провайдеров, API-профили и делегирование между агентами через MCP оркестрации (PR #64).
- Витрина плагинов работает без аккаунта GitHub; вход необязателен и только повышает лимиты GitHub (issue #22). Часы на HOME показывают дату (issue #53).
- Основная сессия отклоняет веб-разрешения, упавший интерфейс перезагружается, длинные ответы агентов сохраняют свой ход, а проверка секретов проверяет и собранный бандл (из PR #35 и #51).

- Включена интеграция Even G2 с локальным сопряжением и голосовым управлением из PR #50.
- Включены документация архитектурных решений, закрепление `js-yaml 4.3.2` и обновления сборочных зависимостей из PR #48 и #49.

## 1.5.0

- Конкурирующие обработчики ПКМ заменены единым контекстным диспетчером. Пустой канвас, цветные зоны и заметки показывают собственные действия; настраиваемый безопасный launcher агентов/терминала используется и в поисковой палитре команд `Cmd/Ctrl+K`.
- Заметки стали полноценными сохраняемыми окнами канваса: редактирование, drag, resize по восьми направлениям, snapping, удаление, детерминированная привязка к зоне и маркеры на мини-карте. Реализация адаптирует исходные идеи заметок и быстрого launcher из PR #23 и сохраняет авторство @TroopJostle.
- Доделано перемещение цветных зон: полностью находящиеся внутри терминалы, Browser/plugin-окна и заметки двигаются синхронно с зоной и сохраняются один раз при отпускании. Targeting зон, магнитная сетка и правила bounds больше не захватывают частично пересекающиеся окна и не телепортируют их после жеста.
- Добавлен обычный click-to-front для всех окон канваса. Нативная поверхность Browser теперь подчиняется renderer-стеку, а диалоги запуска ограничиваются границами до первого кадра и не вспыхивают за правой границей приложения.
- Settings и все меню канваса переведены на новый дизайн с общими токенами приложения, официальными Lucide/provider assets и единым масштабом UI-хрома `0.85–1.25`. Смена палитры автоматически перекрашивает меню, не затрагивая zoom канваса и размер шрифта терминала.
- В «Основные» добавлены независимые настройки сохранения цветных зон и заметок после выхода. Выключение оставляет объекты в текущем запуске, но исключает только выбранную коллекцию из snapshot следующего запуска.
- Управление мини-картой разделено на явные режимы «Клик» и «Перетаскивание». Drag повторяет направление grab пустого канваса без начального прыжка камеры, а неподвижное нажатие в Drag-режиме не выполняет click navigation.

## 1.3.0

- Добавлено опциональное восстановление окон терминалов. CanvasTTY сохраняет только identity окна, provider/profile, заголовок, папку проекта, позицию и размер; агенты продолжают сессию через нативный project-scoped continue mode, а PTY scrollback и capabilities не сохраняются.
- Добавлены именованные пастельные области канваса из контекстного меню пустого пространства и RTS-мини-карта вокруг текущей камеры. HOME и маркеры окон двигаются по единой проекции без auto-fit и искажений; пограничный маркер HOME появляется только после его полного выхода за карту.
- Бинды навигации канваса теперь принимают Mouse3/Mouse4/Mouse5, drag средней кнопкой остаётся прямым fallback для pan. Исправлено владение wheel: список сессий и focused input-поверхности прокручиваются локально, пока пользователь явно не включил перехват канвасом.
- Исправлена обрезанная первая отрисовка Grok Build: запуск, restart и restore ждут реальный размер сетки xterm от renderer. Resize терминала и смена палитры сохраняют текущую позицию scrollback.
- В «Оформлении» появился настраиваемый фон всей строки агента: серый для простоя/недоступного/завершённого состояния, зелёный для работы и жёлтый для ожидания ответа; доступен однотонный режим.
- Лимиты Claude теперь запрашиваются с OAuth credentials текущего пользователя приложения. Отсутствие локального токена означает необходимость входа, а не ошибочное «Требуется подписка».
- CanvasTTY больше не восстанавливает, не показывает и не фокусирует окно из-за отклонённого второго запуска или фоновой активности плагина/браузера, поэтому приложение самовольно не переключает виртуальные рабочие столы.
- Добавлены краткий выключатель status hooks в «Агентах», раскрываемый FAQ в «О приложении» и явное доверие к каждому опциональному plugin agent hook. После install/update хуки выключены и запускаются в изолированном процессе без внутренних capabilities CanvasTTY.

## 1.2.8

- Qwen Code добавлен как полноценный launcher в HOME, Settings, поиск CLI, профили Normal/YOLO, plugin SDK и ограниченный MCP-мост встроенного браузера. Используются официальный mark Qwen и только launch-scoped конфигурация.
- В HOME и его настройках появилась строка лимитов Qwen. Поскольку Qwen Code умеет работать с разными облачными и локальными model providers и не имеет универсального quota-read protocol, CanvasTTY показывает явную причину недоступности, а не выдумывает usage data.
- Общий статус открытой агентской сессии заменён на защищённый локальный lifecycle gateway. Codex, Claude Code, Qwen Code, Kimi Code, OpenCode, Hermes и Grok Build сообщают состояния «Простаивает», «Работает» и «Ждёт ответа» через provider hooks без передачи текста prompt/response; terminal-title markers Claude/Qwen сохранены как fallback совместимости.
- Исправлена гонка, при которой поздний bootstrap snapshot возвращал уже подтверждённый lifecycle агента в состояние «Статус недоступен». Метаданные сессии теперь имеют монотонную ревизию от main-процесса, а renderer отклоняет устаревшие статусы, сохраняя начальный вывод терминала.
- При изменении размера карточки или окна приложения сохраняется активная позиция terminal scrollback вместо прыжка в начало сессии.
- Keyboard focus сегментированной настройки остаётся внутри выбранной кнопки; между переключателем захвата wheel/pinch и условным редактором клавиши восстановлен правильный отступ.

## 1.2.7

- Добавлен узкий мост для управления Hermes Desktop HUD из плагинов. Хост открывает только проверку статуса, запуск в HUD-режиме и закрытие через `hermes:hud`; плагин не может выбирать исполняемый файл, аргументы или PID.

## 1.2.6

- Исполняемые файлы provider CLI теперь один раз определяются при старте и затем используются терминалами, лимитами и agent-browser через один абсолютный launcher; для отсутствующих и неисполняемых команд возвращается структурированная диагностика.
- Неудачные сессии HOME теперь показывают полную очищенную диагностику по наведению или фокусу с клавиатуры, позволяют скопировать её и объясняют тихое завершение кодом выхода. Всплывающая панель верхнего слоя сохраняет трёхрядный scroll viewport и красный danger rail ошибочной сессии.
- Упакованное macOS-приложение теперь находит CLI из Homebrew и официальный пользовательский OpenCode в `~/.opencode/bin` даже при запуске через Finder с минимальным `PATH`.
- CI теперь собирает macOS-приложение и проверяет реальный поиск CLI с минимальным `PATH` для каждого pull request и обновления `main`, а не только во время релиза.
