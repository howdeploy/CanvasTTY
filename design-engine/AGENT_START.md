# Create CanvasTTY artwork with an agent

Start with [LIVE_ENGINE.md](LIVE_ENGINE.md) and choose the output before drawing:

- **Independent wallpaper, Home avatar or clock background:** one local media file or portable `.ctwallpaper`. Use `tools/pack_wallpaper.py --require-live` for live images (or `--verify` for stills) and the prompts in `templates/`. The built-in workshop imports, previews, frames, saves and assigns these assets. No plugin and no dummy terminal frames are required.
- **Terminal skin:** nine frame roles plus one Canvas background in an install ZIP. Read [SPEC.ru.md](SPEC.ru.md) for geometry/apertures. Frame roles are `{minimal,detailed,master}_{idle,working,completed}`. Every role occurs exactly once. New frames are 1536×1024 with a transparent central opening. PNG/APNG, GIF and WebP retain native animation; the separate background also accepts MP4/WebM.

The Live Engine contract requires a supporting CanvasTTY build; verify the target build instead of assuming upstream main or older installed releases support it. Static PNG packs remain compatible with earlier importers.

Use the supplied visual reference or art direction. Preserve source media. Do not embed terminal text, real clock digits, screenshots or app controls in artwork. Keep clock centers readable and avatar subjects inside a square safe area. Report actual source resolution, codec, loop length and file size. Respect reduced motion and avoid flashes.

For a full skin ZIP, validate using the matching CanvasTTY source checkout:

```sh
node scripts/validate-pixel-skin-zip.mjs /absolute/path/theme-install.zip
```

Inspect all nine frames overlaid, confirm stable geometry and transparent apertures, and report per-level insets. Deliver the ten final role files in the install ZIP, without sources, duplicate backgrounds or reports. Matching Live Engine builds also accept optional `layout.json` generated by `pack_terminal_theme.py --controls controls.json`: it stores apertures and measured button plaques. Older ZIPs without it remain supported. Keep a separate copy of geometry for inspection. The offline source kit ZIP is not an install ZIP.

For animation use `tools/encode_animation.py` to assemble real authored frames or a sprite sheet; `tools/animate_artwork.py` provides only a masked brightness effect, not AI object motion. The live packer checks every decoded image frame; video inspection uses ffprobe metadata, while manual app import checks Chromium decoding. Package terminal roles with `tools/pack_terminal_theme.py --apertures apertures.json --require-live --receipt theme-check.json`. Keep reports outside the install ZIP. For high detail/soft alpha prefer APNG/WebP over GIF. Check the actual reference quality before treating a technically valid pack as release-ready. Validate the package with the matching `WallpaperRegistry`, then check the rendered result when possible. Do not claim installation, quality or a successful live-app check from structural validation alone. Keep access credentials local and preserve the owner's other themes and wallpapers.

For calm pixel-art motion, use `tools/compose_pixel_scene.py` with an authored pose atlas. Keep the camera, scenery and global brightness fixed; animate only local objects in integer pixel steps with held poses. Preserve transparent outer space and let ornaments protrude beyond the main rails. Measure control plaques from the final art; check button containment and spacing at several card sizes. Watch multiple loops in the actual app before reporting visual acceptance.
