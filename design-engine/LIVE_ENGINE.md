# CanvasTTY Live Engine · формат 1

Это встроенная система оформления CanvasTTY: Canvas, Home и рамки терминалов. Она не требует плагина. Этот контракт относится к сборке с поддержкой Live Engine; прежние выпуски и upstream main могут его ещё не поддерживать. Не обещайте установку в старый клиент.

## Выберите результат

| Задача | Результат | Импорт |
| --- | --- | --- |
| Обои Canvas, аватарка Home, фон часов | Один `.ctwallpaper` либо отдельное медиа | Оформление → Фоны и живые обои → Мастерская обоев и Home |
| Рамки терминала со сменой состояний | ZIP с девятью рамками и фоном | Создать тему / живой скин |

Обои независимы от рамок. Для своих обоев не нужны девять фиктивных рамок. Один сохранённый фон можно назначить на Canvas, аватарку или часы. Импорт не активирует его сам: пользователь выбирает назначение и нажимает «Сохранить и применить».

## Разрешение и адаптация

- Принимайте PNG/APNG, GIF, WebP, MP4 H.264 и WebM VP8/VP9. Изображение до 20 МиБ, видео до 80 МиБ. Максимум 8192 px по стороне и 36 Мп. Аудиодорожка не воспроизводится.
- Сначала узнайте реальное разрешение (для видео, например, через `ffprobe`). `--source-width/height` должны описывать исходник, а не желаемый размер экрана. Рекомендуемый режим `--verify` определяет размеры и декодирует все кадры изображений (Pillow); `--require-live` дополнительно требует разные кадры и бесконечный цикл. Для видео ffprobe проверяет метаданные/кодек и отсутствие звука, полное воспроизведение проверяется в приложении. Режим с явно заданными размерами без этих флагов только упаковывает байты.
- Рекомендуемые холсты: Canvas 1920×1080 / 2560×1440 / 3840×2160 / 1920×1200 / 2560×1080; Home avatar 512×512; часы 1440×480 или более лёгкий 960×320.
- `recipe.width/height` задают пропорции предпросмотра и холст генерации. Они не означают перекодирование: на реальном рабочем поле изображение подстраивается под размер окна.
- `fit: cover` заполняет область с обрезкой; `contain` показывает исходник целиком. `x/y: 0..100` задают фокус кадра. `pixelated` включает чёткое масштабирование пикселей. Увеличение картинки не создаёт новые детали.
- Оригинал копируется в профиль `wallpapers/<uuid>/media.ext`; рецепт — в `wallpaper.json`. Перезапуск или удаление исходного файла из Downloads не ломает сохранённые обои. Библиотека — до 100 элементов. Экспорт переносит медиа и рецепт вместе.

## Часы и аватарка

Аватарка: центрируйте предмет, оставляйте запас для квадратного кадра; используется виджет Home Media. Часы: фон отдельный, настоящие время и дата остаются живыми элементами интерфейса. Не впекайте цифры в GIF. Держите центр спокойным, не применяйте вспышки, зациклите фон. Шрифты `mono`, `sans`, `serif`, `pixel`; `pixel` использует встроенные пиксельные цифры. `dim: 0..0.9` затемняет фон для читаемости. Анимации учитывают системное уменьшение движения и приостанавливаются, когда область или окно скрыты.

## Переносимый .ctwallpaper

UTF-8 JSON, максимум 113 МиБ. Только данные, без JavaScript, HTML, путей к чужим файлам или внешних URL:

```json
{
  "schemaVersion": 1,
  "kind": "canvastty-wallpaper",
  "name": "Night clock",
  "recipe": {"fit":"cover","x":50,"y":50,"width":1440,"height":480,"pixelated":true,"clockFont":"pixel","dim":0.35},
  "source": {"file":"media.gif","width":960,"height":320,"base64":"..."}
}
```

`source.file` — описание, приложение определяет формат по содержимому, не открывает этот путь. Поле `base64` содержит сам файл. Пакет не зависит от локального пути автора.

```sh
python3 tools/pack_wallpaper.py my-loop.gif my-clock.ctwallpaper --name "Night clock" --source-width 960 --source-height 320 --width 1440 --height 480 --pixelated --clock-font pixel
```

Упаковщик использует стандартную библиотеку Python, не перезаписывает существующие файлы. Без перекодирования сохраните и исходное медиа, и пакет.

## Локальный генератор для агента

`tools/generate_pixel_wallpaper.py` создаёт процедурный пейзаж с seed и палитрой. Нужен Python с Pillow. Вызовы моделей и API не требуются. В CanvasTTY также встроен простой статичный PNG-генератор; GIF создаёт инструмент этого набора:

```sh
python3 tools/generate_pixel_wallpaper.py clock.gif --width 960 --height 320 --seed 42 --palette night
python3 tools/pack_wallpaper.py clock.gif clock.ctwallpaper --name "Pixel night" --source-width 960 --source-height 320 --width 1440 --height 480 --pixelated --clock-font pixel
```

GIF: 24 кадра, 8 fps, период 3 секунды, цикл без разрыва фазы. У генератора ограничена сумма пикселей кадров; не создавайте 4K GIF без необходимости. `--still` и имя `.png` дают статичный фон. Палитры `night`, `forest`, `sunset`. Шаблоны заданий — в `templates/`.

## Установка из CLI

Только через подключение владельца, как и смена тем. Подключение агентской сессии не получает права менять настройки приложения. Не ищите и не передавайте токены.

```sh
node scripts/canvastty-control.mjs wallpaper-list
node scripts/canvastty-control.mjs wallpaper-install --package /absolute/path/clock.ctwallpaper
node scripts/canvastty-control.mjs wallpaper-select wallpaper:UUID --target clock
```

`--target canvas|avatar|clock` у `wallpaper-install` сохраняет и применяет сразу. Установку в пользовательский профиль выполняйте только по поручению пользователя. Валидация пакета не доказывает декодирование/красоту в приложении; отчёт должен различать эти уровни проверки.

## Живые рамки

Девять ролей `{minimal,detailed,master}_{idle,working,completed}`: PNG/APNG, WebP или GIF с прозрачным проёмом. Новые рамки ровно 1536×1024, геометрия всех состояний совпадает. Десятая роль `background`: также MP4/WebM. Один файл на роль, ZIP до 150 МиБ. Размеры и отступы проёма — в SPEC.ru.md. Валидируйте тем же импортёром CanvasTTY; не вкладывайте `.ctwallpaper` внутрь ZIP рамок.

## Локальная интеграция Home

Встроенный виджет поддерживает до шести часовых поясов и восьми таймеров. Фон рисуется под настоящими цифрами, поэтому агент генерирует только оформление; таймеры и реальное время в GIF не впекаются. GIF можно выбрать непосредственно через аватарку Home.

## Сборка анимации из концепта

Python 3.10+ и Pillow нужны для декодирования/кодирования изображений. Старый режим упаковки с явными размерами работает без Pillow. Для видео нужен ffprobe в PATH. Все инструменты работают локально, не вызывают модель и не отправляют исходники в сеть.

1. Создайте качественный исходный арт по референсу. Для движения объектов подготовьте отдельные PNG-кадры: `frame-0000.png`, `frame-0001.png`, … без пропусков, на одинаковом холсте. Рамки — 1536×1024, центр прозрачен в каждом кадре. Не выдавайте увеличенное разрешение за новые детали.
2. Соберите анимацию, затем независимые обои:

```sh
python3 tools/encode_animation.py my-frames/ wallpaper.gif --fps 10 --receipt animation-check.json
python3 tools/pack_wallpaper.py wallpaper.gif wallpaper.ctwallpaper --name "My live wallpaper" --require-live --width 1920 --height 1080
```

Для атласа вместо каталога: `sheet.png output.gif --columns 4 --rows 4 --fps 10`. Ячейки идут слева направо, сверху вниз, без промежутков. `--count` исключает неиспользуемые последние ячейки. Маленькие ячейки атласа не заменяют рамки 1536×1024; для детальных рамок используйте отдельные кадры.

Для лёгкого эффекта поверх статичного арта есть отдельный инструмент:

```sh
python3 tools/animate_artwork.py concept.png wallpaper.apng --seconds 3 --fps 10 --mask glow-mask.png --receipt glow-check.json
```

Маска необязательна: белое анимируется, чёрное сохраняется. Этот режим меняет яркость периодически, не двигает объекты и не является генеративной анимацией. Не применять его как замену художественной проработке. Для GIF доступны 255 цветов и бинарная прозрачность; APNG/WebP сохраняют мягкую альфу и детализацию. Геометрия и альфа рамки остаются неизменными.

Для арта с огнём и лавой доступен более заметный локальный эффект потока и искр (Pillow + NumPy):

```sh
python3 tools/animate_emissive.py forge.png forge.gif --frames 30 --fps 10 --state working --receipt forge-check.json
```

`--state idle|working|completed` меняет активность горна; `--aperture aperture.json` технически очищает проём. Двигаются горячие текстуры и искры, каменная кладка сохраняется. Это локальная анимация исходного арта, не генерация видео моделью. GIF использует общую палитру, а при неизменной маске прозрачности — сжатие изменений между кадрами; меняющаяся альфа очищается отдельно, чтобы не оставлять следы. Проверяйте движение при реальном масштабе Home: различие байтов кадров само по себе не доказывает заметную анимацию.

3. Для терминальной темы подготовьте отдельный каталог только с десятью конечными файлами ролей. Проёмы сохраните отдельно; измеренные плашки кнопок можно передать через --controls controls.json, чтобы добавить layout.json в ZIP:

```json
{"minimal":{"left":8,"right":8,"top":17,"bottom":13},"detailed":{"left":8,"right":8,"top":17,"bottom":13},"master":{"left":8,"right":8,"top":17,"bottom":13}}
```

Это пример, а не обязательные проёмы всех тем: измерьте свои.

```sh
python3 tools/pack_terminal_theme.py final-roles/ theme-install.zip --apertures apertures.json --require-live --receipt theme-check.json
node scripts/validate-pixel-skin-zip.mjs /absolute/path/theme-install.zip
```

Последняя команда выполняется из соответствующего исходного дерева CanvasTTY с Live Engine. Публичный статический upstream может отвергать живые роли. В install ZIP десять медиа и необязательный `layout.json` с измеренной геометрией (см. ниже). Без него `apertures.json` передайте отдельно в диалоге/CLI. `.ctwallpaper` и отчёты хранятся отдельно.

Инструменты не перезаписывают существующие результаты. Лимит кодирования — 96 млн пикселей суммарно по кадрам, проверки — 192 млн на медиа. Это ограничения инструментов для памяти, не новые ограничения формата. При превышении уменьшите fps/длительность или используйте видео для обоев. GIF-тайминги точны для 5/10/20 fps; одинаковые соседние кадры могут объединяться кодером с сохранением длительности.

Автопроверка подтверждает разные декодированные кадры, бесконечный цикл изображений, размеры, лимиты и прозрачный проём. Она не доказывает красивый арт, плавный стык или отсутствие нагрузки. Проверьте стык цикла, все состояния/уровни, читаемость терминала, несколько одновременно открытых карточек, паузу при скрытии и reduced motion в приложении. Отчёт с SHA-256 поставляется отдельно, не внутри установочного ZIP.

## Спокойная покадровая pixel-art сцена

Для неподвижного фона с локальным движением используйте `tools/compose_pixel_scene.py scene.json output.gif --receipt check.json`.
В `scene.json`: `base`, `atlas` (локальные пути относительно JSON), `atlasGrid:[4,2]`, `logicalSize:[640,360]`, `outputSize:[1280,720]`, `frames:32`, `fps:5`, `sprites:[{"rect":[220,146,34,40],"hold":4}]`.
Каждый кадр начинает с одинакового фона. Меняются только нарисованные позы в заданных прямоугольниках, масштабирование nearest-neighbor целым множителем. `embers` задаёт явные целочисленные пути; `null` — пауза. Для рамки добавьте `aperture` и `preserveAlpha:true`. Не деформируйте весь исходник и не меняйте общую яркость вместо движения объектов. `animate_emissive.py` оставлен как отдельный эффект текстуры, он не заменяет покадровую пиксельную анимацию.

У рамки оставляйте прозрачное внешнее поле: шестерни, камни, растения или другие украшения выступают за основные рейки. Центр прозрачен, текст получает подложку самого терминала.

В новых пакетах можно сохранить измеренную геометрию кнопок: `pack_terminal_theme.py ... --controls controls.json`. JSON содержит `minimal`, `detailed`, `master`, для каждого — `left`, `top`, `width`, `height` в процентах исходного изображения. Упаковщик добавит `layout.json` с `schemaVersion:1`, проёмами и плашками к десяти медиа. Актуальный Live Engine читает его и сохраняет при перезапуске; старые ZIP без метаданных совместимы. Проверяйте, что кнопки находятся внутри нарисованной плашки и выше проёма на нескольких размерах. Проверка декодирования и движения не заменяет эту приёмку и просмотр нескольких циклов.

## Несколько локальных движений вместо одного огонька

`compose_pixel_scene.py` поддерживает `flows`: маска `polygon` в логических пикселях, `axis: x|y`, `period:12`, `hold:2`, `sampleOffset`, `phase`, `strength:0.7`, `excludeRects:[[x,y,w,h]]`. Это движение короткой полосы исходной текстуры по целочисленной сетке. По умолчанию маска ограничена горячими пикселями (`hotOnly:true`); холодные камни, рейки и исключённые скобы не меняются. Период `period*hold` обязан делить число кадров: цикл замыкается без большого сброса. Разные объекты получают разные фазы.

Для кузницы: вертикальные каналы расплава, горизонтальная струйка в лотке, языки пламени в топках и редкие искры. Подбирайте движение по существующему объекту. Огонь с восемью позами и hold=2 при 10 fps меняет позу каждые 200 мс. Не раскачивайте всю картинку и не меняйте общую яркость. Не вращайте вырезанный прямоугольник шестерни поверх неподвижного двойника: твёрдым объектам нужны отдельная маска и чистая подложка.

Проверяйте видимые рамки и на уменьшенном Canvas. Режим сводки может отключать содержимое терминала, но сам видимый живой скин должен продолжать движение. Скрытие окна/карточки, выход за экран и системное уменьшение движения по-прежнему ставят медиа на паузу.

Для пламени за решёткой у `sprites` доступны `hotOnly:true` и `excludeRects:[[x,y,w,h]]` в координатах сцены: маска ограничивает нарисованные позы горячими пикселями и сохраняет прутья. Поток текстуры не заменяет силуэт языка пламени; проверяйте обе техники на реальном объекте.
