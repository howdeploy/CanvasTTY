# Canvas Duo: прямое соединение и диагностика

Хост нажимает «Создать и скопировать ссылку», гость вставляет её и нажимает «Подключиться». Один хост и один гость. Выдача управления — отдельное действие хоста. Доступ можно отозвать либо полностью прекратить через Duo.

Поиск компьютера и прохождение NAT выполняет закреплённый HyperDHT 6.36.0 (MIT). Для поиска используется публичная DHT с bootstrap-узлами. Это внешняя инфраструктура обнаружения. Трафик рабочего стола идёт по прямому зашифрованному Noise/UDP/UDX-соединению; дополнительный AES-256-GCM защищает сообщения с проверкой направления. Приглашение содержит ожидаемую гостевую идентичность и секрет доступа. Полная ссылка даёт доступ к опубликованному столу: передавайте её лично.

По умолчанию общий Canvas включает терминалы, заметки, комментарии, Home, файлы, медиа, плагины и браузер. Камера и масштаб независимы у каждого участника. Терминалы исполняются на компьютере хоста; разрешённое управление действует с правами его пользователя. Хост также может ограничиться восемью выбранными терминалами с отдельными разрешениями ввода. Системные окна вне Canvas не передаются.

При разрыве/истечении аренды права управления отзываются. Переподключение восстанавливает транспорт, но не повторяет команды с неоднозначным результатом и не возвращает прежнее разрешение управления автоматически. Приглашение ограничено часом для нового подключения; уже активная сессия живёт, пока поддерживается связь. Закрытие панели не завершает соединение; используйте «Отключиться».

Прямой P2P не гарантируется во всех сетях: блокировка UDP или несовместимый NAT могут помешать подключению. Relay-fallback отсутствует. Успех на одной паре сетей не доказывает работу на всех провайдерах.

## Когда не подключается

Откройте Duo → «Проблема с подключением?» → «Скопировать диагностику Duo» на обоих компьютерах. Скопируйте отчёты сразу после сбоя: в памяти остаются последние 200 событий текущего запуска. Отчёт не отправляется автоматически.

Каждая попытка имеет случайный `attempt`, время, роль, транспорт, этап и длительность с начала попытки. Для повторного соединения создаётся новый идентификатор. Последовательность гостя: `attempt-start` → `connect-start` → `encrypted-open` → `snapshot-start` → `connected`. У хоста: `listen-start` → `listening` → `encrypted-open` → `peer-authenticated`. Есть события разрыва, остановки, истечения аренды, медленного запроса, переподключения и отказа.

Коды ошибок берутся из ограниченного списка, текст исключений не копируется:

- `PEER_NOT_FOUND`: DHT не нашла адресата; проверьте, что хост ещё работает и ссылка свежая.
- `CANNOT_HOLEPUNCH`, `HOLEPUNCH_DOUBLE_RANDOMIZED_NATS`, `HOLEPUNCH_PROBE_TIMEOUT`: не получился прямой путь через NAT.
- `DIRECT_CONNECT_TIMEOUT`: истёк срок открытия транспорта, без доказательства конкретной причины.
- `ECONNREFUSED`, `ENETUNREACH`, `EHOSTUNREACH`, `ENOTFOUND`: сетевой отказ соответствующего уровня.
- `INVITATION_REJECTED`, `INVALID_INVITATION`: отклонённое/некорректное приглашение.
- `RPC_TIMEOUT`: ответ не пришёл вовремя; команда могла дойти, повторять автоматически нельзя.
- `UNKNOWN`: библиотека вернула нераспознанную причину; точный вывод о NAT делать нельзя.

В отчёте нет IP, портов, ключей, приглашений, имён/путей файлов, ввода или вывода терминала. Успешные heartbeat/обновления не записываются. Повторы соседних одинаковых событий подавляются на пять секунд. Метаданные также записываются в штатный локальный `logs/application.jsonl` профиля приложения с ротацией (четыре файла до 1 МиБ). Общий журнал приложения может содержать сведения других подсистем; кнопка Duo копирует только ограниченный отчёт Duo.

## Проверка

`npm run typecheck`; `node --test tests/canvas-duo.test.mjs tests/duo-*.test.mjs`. Локальная тестовая DHT использует реальные сокеты без обращения к публичной сети. Отдельно проверяются сохранение безопасного кода после неудачного соединения и отсутствие секретов в отчётах. Это не заменяет приёмку Mac ↔ Windows/Linux через разные внешние сети.

Обработчик `canvasduo://` поддерживает холодный запуск, macOS open-url и Windows/Linux second-instance. Проверка обработчика и IPC отдельно от регистрации протокола установленной ОС. [HyperDHT](https://github.com/holepunchto/hyperdht).
