# Метрики и телеметрия

[English](metrics-and-telemetry.md) · [Русский](metrics-and-telemetry.ru.md) · [简体中文](metrics-and-telemetry.zh-CN.md) · [Документация](README.ru.md)

CanvasTTY рассматривает телеметрию сначала как проблему достоверности и лишь потом — как проблему визуализации. Идеально отрисованный индикатор прогресса всё равно врёт, если его источник не может подтвердить значение.

## Не смешивайте разные измерения

| Измерение | Смысл | Пример источника |
|:--|:--|:--|
| Квота подписки | Использование внутри заданного провайдером окна и время его сброса | Официальный эндпоинт использования аккаунта или структурированный CLI-протокол |
| Токены сессии | Input-, output- и cache-токены, относящиеся к одной сессии | Структурированные lifecycle- или usage-события провайдера |
| Стоимость | Списанная сумма в валюте при известной модели и источнике цены | Официальная запись billing/usage, а не умножение токенов на угаданную цену |
| Прошедшее время | Длительность по часам от известной временной метки сессии | Локальные монотонные/системные часы плюс реальные метки lifecycle-событий |
| Состояние активности | Работает ли агент или ждёт подтверждения | Структурированный lifecycle-сигнал провайдера |

Процент подписки нельзя вывести из токенов сессии. Количество токенов само по себе не доказывает стоимость. Вывод PTY не доказывает активность.

## Что уже есть

[`LimitsService`](../src/main/services/LimitsService.ts) читает окна подписки провайдера через структурированные адаптеры:

- Codex — через app-server-протокол установленного CLI.
- Claude и Kimi — через их эндпоинты использования, доступные только для чтения, если это поддерживают учётные данные и тип аккаунта установленного CLI.
- Кэш на 60 секунд с возвратом к stale-данным после ранее успешного чтения.
- Очищенные снапшоты `available`, `stale` или `unavailable`; сырые учётные данные и ответы провайдера никогда не пересекают IPC.

CanvasTTY никогда не разбирает терминальный UI провайдера, чтобы восстановить лимиты. Неподдерживаемые типы подписки остаются явно недоступными.

## История использования

Откройте **«История использования»**, чтобы выбрать период и увидеть измеренные изменения
квоты, условные оценки по приложению → профилю → сессии и локальные счётчики токенов.
Период отчёта не меняет окно квоты: основное и недельное окна показываются отдельно.

- Квоты Codex/Claude опрашиваются раз в минуту, пока работает CanvasTTY.
- Локальные журналы Codex, Claude Code и базы Hermes доступны только для чтения.
  Для Hermes нужен SQLite CLI с поддержкой `-safe` в `PATH`; отсутствие источника не означает нулевой расход.
- История и курсоры атомарно сохраняются в `usage-history.json` в обычном каталоге
  Electron `userData`; пределы — 30 дней и 500 000 событий.
- Автоматическая оценка распределяет измеренное изменение сопоставимого интервала по
  весам токенов сессий, **если это изменение объясняется локальной активностью**.
  Это не формула биллинга провайдера и не доказательство списания с конкретного аккаунта.
  Вклад других устройств и неучтённых источников остаётся неизвестным.
- Неполный сбор, ожидающие учёта события, сбросы, смены аккаунтов и пропуски обозначаются
  явно. Прошлые проценты квоты нельзя восстановить из суммы токенов.
- В главный renderer передаются только метаданные учёта, без запросов, ответов и секретов.
  Плагинам API этой истории не предоставляется.

Описанный ниже API токенов остаётся предлагаемым контрактом расширения. Встроенная история
использует [`UsageHistory`](../src/shared/usageHistory.ts), а не этот публичный контракт.
Проверка в Electron: `node scripts/smoke-usage-ui-packaged.mjs --app <package>`.

## Приоритет источников

Берите самый высокий доступный источник и останавливайтесь, если доверять нечему:

1. Структурированное событие провайдера или локальный протокол, привязанные к session ID.
2. Официальное usage API провайдера со стабильными идентификаторами.
3. Документированный JSON-вывод CLI, предназначенный для автоматизации.
4. `unavailable` с конкретной причиной.

Не скрейпьте ANSI-вывод, не вычисляйте работу агента по тексту терминала, не оценивайте токены по символам, выдавая оценку за факт, и не передавайте auth-данные в renderer. Оценка может существовать только как отдельно обозначенная величина с явными методом и неопределённостью; она никогда не должна подменять реальное usage-поле.

## Предлагаемый контракт токенов сессии

Discriminated union не даёт недоступным данным притвориться нулями:

```ts
type SessionMetricSource =
  | "provider-event"
  | "provider-usage-api"
  | "cli-json";

type SessionMetricUnavailableReason =
  | "unsupported-provider"
  | "not-authenticated"
  | "not-reported"
  | "timeout"
  | "protocol-error";

interface SessionTokenValues {
  inputTokens: number | null;
  outputTokens: number | null;
  cachedTokens: number | null;
  totalTokens: number;
}

type SessionTokenUsage =
  | {
      sessionId: string;
      provider: AgentProviderId;
      state: "available";
      source: SessionMetricSource;
      fetchedAt: number;
      values: SessionTokenValues;
    }
  | {
      sessionId: string;
      provider: AgentProviderId;
      state: "stale";
      source: SessionMetricSource;
      fetchedAt: number;
      failedAt: number;
      reason: SessionMetricUnavailableReason;
      values: SessionTokenValues;
    }
  | {
      sessionId: string;
      provider: AgentProviderId;
      state: "unavailable";
      checkedAt: number;
      reason: SessionMetricUnavailableReason;
    };
```

Оставляйте вложенные поля nullable, если источник достоверно сообщает только total. Никогда не вычисляйте отсутствующую разбивку input/output. До создания снапшота проверьте каждое число на конечность, неотрицательность и вхождение в безопасный диапазон.

## Поток данных токен-виджета

```text
структурированный источник провайдера
        ↓
адаптер main-процесса
  валидация · нормализация · кэш · привязка к session ID
        ↓
очищенный снапшот SessionTokenUsage
        ↓ IPC из белого списка + типизированный preload
чистый селектор renderer
        ↓
виджет Home или сводка карточки терминала
```

Main-адаптер отвечает за авторизацию, таймауты, специфичные для провайдера схемы, дедупликацию и очистку. Renderer отвечает только за представление и локальный выбор. Если провайдер не может привязать usage к конкретной сессии CanvasTTY, нельзя приписывать этой сессии токены всего аккаунта.

## Поведение виджета

- Показывайте компактное числовое итоговое значение только в состояниях `available` и `stale`.
- Помечайте устаревшие данные как stale, не заменяя их нулём; метка времени источника должна быть доступна в assistive-тексте или в деталях.
- Вместо пустого индикатора показывайте локализованную причину недоступности.
- Детерминированный индикатор прогресса допустим, только когда есть реальный знаменатель. Сам по себе расход токенов обычно не имеет знаменателя.
- Не смешивайте lifetime/session-итоги с окнами квоты провайдера.
- Пассивная метрика на Home не должна перехватывать колесо мыши.
- Ограничивайте историю по числу событий или по времени. Агрегация не должна бесконтрольно раздувать память renderer или сохранённое состояние.

## Приватность и безопасность

- Возвращайте счётчики и минимум метаданных источника, но не промпты, ответы, буферы терминала, токены аккаунта, cookies или сырые payload провайдера.
- Читайте учётные данные провайдера только в доверенном main-процессе и отправляйте их только на соответствующий официальный эндпоинт.
- Вырезайте чувствительные данные из stderr подпроцессов перед логированием: инструменты провайдера могут выводить чувствительные пути и идентификаторы.
- Не собирайте телеметрию по каждому нажатию клавиши. Предпочитайте агрегаты, сообщаемые провайдером, или укрупнённые lifecycle-события.
- Задавайте явные сетевые таймауты и завершение подпроцессов, чтобы зависший адаптер не блокировал выход из приложения.

## Кэш и свежесть

Выбирайте свежесть по смыслу данных, а не ради анимации. Для квоты подписки допустим кэш на минуту; токены сессии можно обновлять по структурированному событию message/completion. Дедуплицируйте параллельные обновления. После временной ошибки сохраняйте последний валидный снапшот как `stale`, но не храните его бессрочно без видимого возраста данных и политики истечения.

## Матрица тестов

Как минимум покройте:

| Область | Случаи |
|:--|:--|
| Нормализация | полный payload, payload только с total, ноль токенов, повреждённые/отрицательные/неконечные значения |
| Идентичность | правильная привязка сессии, неизвестная сессия, несовпадение провайдера, ответ на весь аккаунт без ключа сессии |
| Состояние | loading, available, stale fallback, причина unavailable, ошибка первого чтения |
| Жизненный цикл | дедупликация параллельных обновлений, таймаут, завершение подпроцессов, удаление сессии |
| Безопасность | в снапшотах и логах нет учётных данных и сырых payload, только IPC из белого списка |
| Представление | нет выдуманного знаменателя, пометка stale сохранена, причина unavailable локализована, колесо мыши не перехватывается пассивным виджетом |

Запустите точечные unit-тесты адаптеров и чистых селекторов, затем `npm test`, `npm run typecheck` и `npm run build`. После этого проверьте настоящий виджет в Electron в обычном масштабе и при отдалении.

Размещение реализации и визуальные правила: [Создание виджетов](widget-authoring.ru.md).
